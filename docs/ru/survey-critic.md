## 1. The OG card — not mentioned once in eight surveys

`seo-surface` counted "four og:image tags" and never opened the image.

`/Users/yury/Documents/coinliqui/public/og.svg` is a 1200×630 card with **English text baked into it** — line 14 `Coinliqui`, line 16 `Perpetual funding rates, open interest and liquidation levels`, line 18 `Free · no account · nothing to sign · coinliqui.com`. `scripts/gen-og-png.mjs:49` reads that one file and `:72` writes `public/og.png`. There is exactly one card for the whole site, hardcoded three times in `src/layouts/Base.astro` — `:188` (JSON-LD `Organization.image`), `:273` (`og:image`), `:280` (`twitter:image`), all `` `${base}/og.png` ``. So every `/ru/` page shared to Telegram, VK, WhatsApp or Slack previews with an English sentence under a Russian title, on a card that is also the Organization's `image` in the graph.

Three consequences nobody costed:

- A `og.ru.png` needs a second SVG, and `gen-og-png.mjs` has no locale dimension at all: it hardcodes `public/og.svg` → `public/og.png` with no argument. It also requires `CF_ACCOUNT_ID` plus a live `~/.wrangler` OAuth token (lines 35–47) and is deliberately **not** in `npm run build` (comment lines 16–19: "a build that fails because a token expired is a build that gets bypassed"). So the ru card is a committed artifact regenerated by hand, i.e. a second thing that silently goes stale.
- `scripts/verify-live.mjs:1063–1068` asserts `og:image` and `twitter:image` are present and **equal to each other**. Per-locale cards must move both, together, or the live gate fails.
- Cyrillic in the card is a rasterisation risk the English path never exercised: `og.svg:2–5` records that the card deliberately uses a generic font stack because `/privacy` promises zero off-origin requests. Cloudflare's Browser Rendering headless Chrome must have a Cyrillic-capable face in that fallback chain, and `gen-og-png.mjs` only validates the PNG magic bytes (`:63–67`) and the IHDR dimensions (`:69–70`) — it cannot see tofu boxes. There is no visual check anywhere.

## 2. `gen-assets.mjs` — the cache-bust graph has exactly one dependency edge, and a locale table is the second

`scripts/gen-assets.mjs:33–39` hashes every `public/*.js` over **itself plus `shared.js`, and nothing else**. Its own header (lines 21–32) explains why: `interact.js` imports `shared.js`, Pages serves `public/` at `max-age=14400`, so a change to `shared.js` invisible to `interact.js`'s URL means four hours of new markup against old script — "the exact failure this file was written to prevent, reintroduced one import deeper."

Every plausible i18n implementation reintroduces it a second time. The moment a Russian strings table or plural-rule module lands in `public/` and is imported by `interact.js`/`typeahead.js`, that file's bytes change while `interact.js`'s hash does not, and `Base.astro:1523–1524` emits the same `?v=` for four hours. Russian readers get English strings from a cached table with no error anywhere. The fix is one line in `gen-assets.mjs` — but only if someone remembers the file exists, and no survey named it.

## 3. IndexNow — yes, it is a burst, and the baseline exemption does not apply

`worker/indexnow.ts` answers the brief's question precisely, and against it.

The "first run is not a change" guard at the top of `stepIndexNow` fires only on `if (!st || !st.known.length)` — an **empty** state. Production state is populated, so a mirrored ru tree makes `fresh = current.filter(u => !known.has(u))` equal to *every ru URL at once*: ~24 static + ~51 funding + ~52 liqmap + ~10 coins ≈ **137 URLs in a single pass**, under `MAX_URLS = 200`, so nothing is held back. Fanned to all five endpoints in `ENDPOINTS`.

The file already measured what a sixth of that does. Its `backoff` doc block records: announcing **22** previously-unannounced URLs returned `api.indexnow.org 429, bing.com 429, yandex 200, seznam 200, naver 200` — and that the byte-identical payload returned 200 from a laptop, i.e. Microsoft throttling Cloudflare's shared egress, not this site. `retryDelayMs` is 5 min doubling, capped at 12 hours. So the ru launch does three things at once: it is the exact bulk-dump pattern the file header calls "indistinguishable from spam"; it very likely 429s both Microsoft endpoints; and the resulting Bing backoff **delays announcement of genuinely new English URLs** — a contract crossing the OI floor during the window waits up to 12 hours. `scripts/indexnow-drain.mjs` exists precisely for that state and would be needed on day one.

Nothing in the codebase can express "these URLs are a baseline, don't submit." The only clean route is to write the ru URLs into `SNAPSHOT["indexnow:state"].known` **before** they appear in a sitemap, or to keep the first slice under the measured 22.

## 4. The weekly report abandons — and takes the ingest pipeline with it

`seo-surface` said `worker/report.ts` "needs no edit". It needs a redesign or a smaller slice.

- `worker/report.ts:98` — `RUN_CEILING_MS = 2 * 3_600_000`.
- `:109` — `SLICE = 20`.
- Coverage phase (`:330`) walks `SLICE * 2` = 40 URLs per five-minute tick, each with a retry on non-200.
- Inspect phase (`:466`) walks `SLICE` = 20 URL-Inspection calls per tick.
- Then two more phases (`search`, `crawlers`).

At 133 URLs that is roughly 3–4 ticks of coverage plus 7 of inspection — comfortably inside two hours. **Double the URL set and inspection alone becomes ~14 ticks (70 min) on top of ~7 of coverage (35 min)**, before the search and crawler phases run. The run crosses the ceiling and hits the abandon branch at `:271–284`, which publishes a partial report reading *"Abandoned after N minutes in phase `inspect`."*

The cost is not the report. Read `:274–276`: **"A run holds the ingest tick — flips, IndexNow and all four candle sweeps stand aside while it walks."** So doubling the URL count converts the site's weekly SEO instrument into a two-hour weekly outage of the data pipeline, every Monday, and then loses the reading it was holding the pipeline for. That is an SEO change landing as a data-freshness regression, which is the one thing this site's entire product claim rests on.

Second-order: `report.ts:307` derives a template's name from the child-sitemap filename, so ru URLs folded into existing children make per-template indexation unreadable (survey caught this). But `scripts/gsc-report.mjs:60` also queries `dimensions: ["query"], rowLimit: 25` against one `sc-domain:` property — Russian and English queries merge into a single top-25 list and a single site-wide average position. The site's stated *only constraint* becomes a blended number across two languages with no way to separate them at that call site.

One shared KV serves both trees; nothing forks.

But the *state machine over* that data speaks English, and one instance is on the homepage:

**`src/lib/flips.ts:293–306`, `describeCoverage()`** — four English sentences generated from D1/KV state ("The flip feed reads the funding-history database, and it is not answering here.", "Collecting funding snapshots since … — N hour(s) of history so far…", plus a binary `hour${h === 1 ? "" : "s"}`). Rendered at `src/pages/index.astro:266` and `:323`. No survey named this function. It joins `freshness()` (`src/lib/freshness.ts:99–137`) and `coldStart()` (`src/lib/hyperliquid.ts:498–519`) as prose the templates do not own: **the three places where the infrastructure explains itself in English, all of which surface on a Russian page precisely when something is wrong** — i.e. at the moment a reader most needs to understand.

## 6. The 404, the 410, and the asymmetry between them

`content-pages` and `routing` both got the single-not-found-route constraint right. Two things they missed:

- `src/pages/404.astro` is not just prose — it is a **link source**. Line 64 renders a chip strip of the twelve largest contracts as `/funding/${symbol.toLowerCase()}` plus `:65` "All N →", and lines 69–88 four English cards to `/funding`, `/liquidations`, `/open-interest`, `/methodology`. A Russian miss therefore lands on an English page whose entire body is a set of exit links **out of the Russian tree**. The page also reads the live snapshot (`:16`) deliberately without a `coldStart()` guard (`:12`).
- **`/retired` is not subject to the same constraint and nobody noticed.** `src/pages/retired.astro:22` sets `Astro.response.status = 410` on an ordinary route precisely because 404.astro cannot set its own status (its comment at `:12–18` records the measured failure). So `src/pages/ru/retired.astro` *is* buildable and *will* be served with 410, unlike a ru 404. That asymmetry is worth writing down: the retirement path can be localised cleanly and the not-found path cannot. `retired.astro:27` also carries a seventh `toLocaleDateString("en-GB")` site (the `formatting` survey listed seven and did not include this one among its named sites; it is real and rendered inside a sentence).

## 7. The client-side search index — the gate forces one document, and the client cannot cope with it

`seo-surface` offered "either a second `/ru/search-index.json` … or one document carrying per-locale pairs" as if both were open. **Option A fails the gate as written.** `scripts/checks.mjs:388–403` `searchIndexGaps` fetches `/sitemap-index.xml`, collects every `<loc>` across every child, and returns anything absent from the single `/search-index.json`. A ru URL in any sitemap and not in that one document is a build failure. So the index is forced to ~266 rows, shared.

`public/typeahead.js` then breaks in four ways nobody stated:

- `:9` fetches the fixed path with no locale notion — every reader downloads both languages' rows on first keystroke, doubling a payload served on every page.
- `:22–23` `hit()` matches `label`, `alt` **and `kind`**. `kind` values are the untranslated machine strings `funding`, `liqmap`, `coin`, `tool`, `section`, `reference`. An English reader typing "funding" matches every ru row too.
- `:28` dedups by `href` — and `/funding/btc` ≠ `/ru/funding/btc`, so both survive as "two different answers to one question", the exact thing the comment at `:24–26` exists to prevent.
- `:28` then truncates to `slice(0, 8)`. With both trees in one array, roughly half of any broad query's eight slots point into the wrong language, from the search box that sits in the topbar of every page.

Fixing this means adding a locale field to the index and a filter in `typeahead.js` — which is a `public/` change, which is finding #2's cache-bust hazard.

## 8. Structured data — one language field, one `@id`, and a graph that contradicts itself

`grep -rn "inLanguage\|contentLanguage\|content-language" src/ scripts/ worker/ public/` returns exactly **one** line: `src/layouts/Base.astro:179`. `src/middleware.ts` sets `content-type`, `x-content-type-options`, `referrer-policy`, HSTS, `permissions-policy` and CSP — **no `Content-Language` header anywhere**, which is a free, `Vary`-safe, path-derived addition the middleware is the natural home for.

The type inventory is small — `WebPage`, `BreadcrumbList`, `WebSite`, `Organization`, `Person`, `ListItem`. `shared-chrome` caught the `WebSite` `@id`/`inLanguage` contradiction. It did **not** catch the sharper instance one node down: `Organization` at `${base}#org` carries `description: IDENTITY.summary` and `disambiguatingDescription` (`Base.astro:189–190`) — the two paragraphs `content-pages` says must be translated. Translating them emits **the same `@id` with two different descriptions**, on a node type that has no `inLanguage` slot at all and no language-neutral way to disambiguate. The Organization is one legal entity; you cannot give it a Russian twin `@id` without asserting two organisations. The only honest shape is: `Organization` and `WebSite` stay English and singular, and `inLanguage` moves down to the per-URL `WebPage` node at `Base.astro:142–148`, which currently carries no language field. That is a decision, not a translation, and it should be made before the first ru URL exists.

Also `crumbNode`'s `@id` at `Base.astro:150` is `` `${Astro.url.pathname}#breadcrumb` `` — **relative, missing `${base}`** unlike every sibling node. Pre-existing; it happens to stay unique across locales, so it is not a locale blocker, but it is the one node whose `@id` would need no change for the wrong reason.

## 9. `Related.astro` — it is the *only* contextual-link mechanism on prose pages, and it is on 12 files

Measured: `grep -rn "<Related" src/pages` → **13 usages across 12 files**, and every one is a prose or reference page (`about`, `data-sources`, `privacy`, `terms`, `methodology/index`, `methodology/liquidations`, `learn/index`, the four `learn/*` explainers, `unlocks`). **Zero data templates use it** — they use chip strips instead.

Answer to the brief's question: `Related` cannot link across locales, because every `href` arrives as a prop from the calling page (`Related.astro:14–15`); the component itself has one literal, the default `title = "Where to go next"`. And it *must not* link across locales, on the component's own stated rule (`Related.astro:9–12`: "a link is a promise that something is on the other side of it") — but the corollary is the part that matters for planning: **on a Russian prose tree, `Related` is the entire internal link graph.** There is no chip strip on a prose page. If the ru `Related` items point at English URLs, the ru pages have literally zero contextual outbound links inside their own tree and zero contextual inbound.

## 10. The link-graph instrument is measuring the footer, and that changes what `underLinked` will do to `/ru/`

This is the finding I would flag hardest, because it makes a gate prediction that is the opposite of what the surveys assumed.

`scripts/verify-live.mjs` (~line 338) states the measurement rule: *"CONTEXTUAL LINKS ONLY — inside `<main>`. The nav rail and the footer link the same set from all 133 pages, so counting them would give every page in the nav 132 inbound … which measures the nav rather than the site."* The scan slices between `<main` and `</main>`.

But in `src/layouts/Base.astro`: `<main class="page">` opens at **:1494**, `<footer>` opens at **:1496**, `</footer>` closes at **:1514**, `</main>` closes at **:1515**. **The footer is inside `<main>`.** Only the nav was actually excluded. So the eighteen `FOOTER_LINKS` destinations (`src/lib/site.ts:365–387`) plus `/data-sources` and `/terms` from the credit line are already counted as contextual inbound on every one of the 133 pages.

Consequences for `/ru/`, both concrete:

- If the ru footer carries **ru** hrefs, every ru page listed in `FOOTER_LINKS` clears `underLinked`'s floor of 5 (`scripts/checks.mjs:2061`) the moment six ru pages exist — trivially, without a single real editorial link. The gate meant to protect the ru tree's link graph would be satisfied by chrome.
- If the ru footer keeps **English** hrefs, the reverse: every ru page sits at 0–1 contextual inbound and lands squarely in the 2–4 band that `checks.mjs:2036–2040` and `src/components/LiqMap.astro:63–83` both record as the measured non-indexed cohort — *"eight of the ten Google has not indexed sit at 2-4 inbound links."*

Either way the gate is not doing what a planner would assume it is doing, and the 60–90 links/page constitution is currently satisfied on data pages by ~50-item chip strips (`LiqMap.astro:76–83`: "from 21 outbound internal links to about 69") which a small ru tree cannot reproduce because there are no ru siblings to link to.

# The three questions

## 1. The single largest hidden cost

**Every quality guarantee this site has is expressed as an English-language assertion over rendered HTML, so a second locale does not add a translation layer — it forks the verification and measurement system, and the fork is mostly silent.**

The `gates` survey counted ~45 English literals asserted against HTML and split them into "fails loudly" and "passes by looking at nothing." That is the right diagnosis and it understates the cost, because the same property holds one level up, in the instruments this project uses to know whether it is winning:

- `worker/report.ts` self-abandons at `RUN_CEILING_MS` (`:98`) on a doubled URL set **and holds `flips`, IndexNow and all four candle sweeps while it does** (`:274–276`). The site loses its weekly indexation reading *and* five minutes of data freshness per tick for two hours.
- `report.ts:307` names templates by sitemap filename, so per-template indexation — the one series that told this project indexation was solved at 86% — becomes unreadable unless ru gets its own children.
- `scripts/gsc-report.mjs:60` blends both languages' queries into one top-25 and one average position, which is the exact number the brief calls the site's only constraint.
- `scripts/verify-live.mjs`'s link-graph instrument is already counting the footer (finding 10), so its verdict on the ru tree will be structurally wrong in whichever direction the ru footer points.

So the hidden cost is not the ~11,000 words or the ~700 template strings. It is that after the translation ships you no longer have a working answer to *"is it working?"* — and the failure arrives as green checks and a stalled cron, not as a red build.

## 2. Is a Russian locale a genuinely bad idea here?

**Not intrinsically. Right now, in this codebase, yes — and I would say so plainly.** Three reasons, in order of weight:

1. **It attacks the instrument at the moment the instrument is the point.** The project just reached 86% indexation with zero rejections and states that *position* is the only remaining constraint. Doubling the URL set from ~133 to ~266 is precisely the intervention `src/pages/sitemaps/liquidation-symbols.xml.ts:9–18` argues against for *49* URLs — that it would move a template "from 1-of-3 indexed to 1-of-52 overnight and make the weekly per-template series meaningless in both directions." Doing it to every template at once, while also breaking the report that produces the series, means you would be flying blind through the exact period you are trying to measure.

2. **The legal and quotation surface cannot be translated, only re-authored.** `src/pages/privacy.astro` (295 lines, dated measured claims, `const updated` at `:61`), `src/pages/terms.astro` (139 lines, exclusions and a licence split at `:117–127` written to undo an accidental sub-licence), and the four verbatim Coinbase Market Data clauses at `src/pages/data-sources.astro:75–81`. A second Russian version of these is a second legal text with no governing-language clause, forking on every future analytics or terms change. And `privacy.astro:155–162` publishes a reasoned position that no consent banner is required — publishing that argument in Russian under `/ru/` is itself evidence of targeting a Russian-speaking audience, which changes the regulatory frame the argument is answering.

3. **Half the gate suite would go silently blind on Cyrillic** — `chartAgreement`, `contradictoryStates`, `handRolledLegends`, the cadence and permission scanners — which by this repository's own written standard (`scripts/checks.mjs:691`, "A check that cannot fail is worse than no check, because it is quoted as evidence") is worse than not having them.

What would make it a good idea: if there is measured Russian-language search demand for these queries that the English tree cannot capture. Nothing in this repo measures that. `scripts/gsc-report.mjs` never requests the `country` dimension, so the project does not currently know what share of its impressions come from Russian-speaking markets. **That measurement costs one query parameter and should precede the decision** — this codebase's own rule is to check the instrument and the premise before changing anything.

## 3. The smallest coherent first slice

The slice has to satisfy five hard constraints simultaneously: `duplicateHeadMetadata` (`checks.mjs:2094`) forbids any untranslated title or description, so partial pages are impossible; `underLinked` (floor 5) forbids an isolated page; `searchIndexGaps` forbids a sitemapped URL missing from the one search index; the IndexNow burst must stay under the measured 22; and the report must stay under two hours. That means the first slice must be a **small, self-linking, store-light, quotation-free cluster in its own sitemap child** — not a scattering of the "most important" pages.

**Phase 0 — no `/ru/` URL exists yet, nothing is sitemapped, nothing is announced.**
1. Per-request locale: `Base.astro:230` (`<html lang>`) and `:179` (`inLanguage`), derived from `Astro.url.pathname`, not a prop. Decide at the same time that `Organization`/`WebSite` stay English-singular and `inLanguage` moves to the `WebPage` node (`:142–148`).
2. Reciprocal `hreflang` + `x-default` in `Base.astro` from an explicit en↔ru path table. `/ru` with **no trailing slash** (`src/middleware.ts:26–31` 301s `/ru/` → `/ru`).
3. Locale-parameterise `public/shared.js` in place — `nf` (`:88`), `usd` (`:129`), `ageWords` (`:71–77`), `paysLabel` (`:38`) — because `duplicateRuleImplementations` (`checks.mjs:530–558`) forbids a second definition of those names under `src/`, `public/` or `worker/`. Same pass: `parseCell` in `public/interact.js:836–848` (the silent 100× sort error), a locale hook via `document.documentElement.lang`, and `gen-assets.mjs:33–39` taught about any new `public/` dependency.
4. Russian `describeCoverage` (`src/lib/flips.ts:293–306`), `freshness()` (`src/lib/freshness.ts:99–137`), `coldStart()` (`src/lib/hyperliquid.ts:498–519`), and the month table (`src/lib/chart.ts:140` and its three copies).
5. `og.ru.svg` → `og.ru.png` via a `gen-og-png.mjs` that takes a filename, plus a per-locale `og:image` at `Base.astro:188/273/280`.
6. A ru `FOOTER_LINKS` and `NAV` listing **only pages that exist** — shorter than the English one, per `Related.astro:9–12`. Fix `isActive` (`Base.astro:64`).
7. Seed `SNAPSHOT["indexnow:state"].known` with the eight ru URLs *before* they enter a sitemap.

**Phase 1 — ship these eight URLs, in this order, in one commit, in a new `src/pages/sitemaps/ru-learn.xml.ts`:**

1. `/ru` — the cluster's hub. **Not** a translation of `src/pages/index.astro` (store-bound, flip feed, `parts[]` bold-tuple h1, chip strips). A purpose-built Russian landing page that reads the snapshot for one opening figure (`openingFigure` floor) and links all seven siblings.
2. `/ru/learn/liquidation-price`
3. `/ru/learn/liquidation-heatmap`
4. `/ru/learn/funding-rate`
5. `/ru/learn/open-interest`
6. `/ru/learn`
7. `/ru/methodology/liquidations`
8. `/ru/retired` — cheap, and the only error-adjacent route that *can* set its own status (`retired.astro:22`).

**Why exactly these.** They are the demand-driven explainer cluster, they are the only pages that already carry `<Related>` (the sole contextual-link mechanism on prose pages, so repointing its items at ru siblings gives the cluster its own graph), and — measured, not assumed — **none of them renders a `pays-` class, `paysClass`, or a `LEGEND_*` constant**, so none of them trips `colourLegend` (`checks.mjs:917–931`), the check that fails loudest on Cyrillic. Two of them (`liquidation-price`, `liquidation-heatmap`) read no live store at all and translate as flat text. `methodology/liquidations` is 582 words with zero interpolations and is the site's flagship credibility page — with the Binance and Lunde quotations kept in English with a Russian gloss. Eight URLs is under the 22 that produced 429s, and adds ~4 minutes to the weekly report.

**Explicitly excluded from the first slice, and say so out loud:** `/ru/privacy`, `/ru/terms`, `/ru/data-sources` (second legal texts and verbatim licence quotations); `/ru/about` (five runtime branch points and `founderAgreement`'s English regex at `checks.mjs:1035`); all five calculators (client-side English rebuilt on every keystroke); and all ~110 data templates (chip strips, `quotable`, `lede`, `parts[]`, and the sortable-table `parseCell` inverse). The English footer and rail on those pages stay exactly as they are — no existing English URL changes.

**Gate edits the slice forces in the same commit:** `scripts/smoke.mjs` ROUTES +8; `PROSE_ROUTES` (`checks.mjs:2380–2396`) + the store-free ru paths, each with a written reason; `src/pages/search-index.json.ts` +8 rows with Russian labels and Russian `alt` search intent; `STATIC_ROUTES` (`src/lib/routes.ts:70`) and therefore `publishedUrls`; `scripts/gen-lastmod.mjs` ROUTES +8 keyed to each ru file's own commit; a new row in `src/pages/sitemap-index.xml.ts:27–43`; and `scripts/freshness-cases.mjs:84–89` and `:119–127`, which pin English age strings.
